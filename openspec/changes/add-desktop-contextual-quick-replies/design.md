## Context

基于公开仓 `dev-1.2.1`（`bc228664`）。桌面 `/chat` 在 `server.ts` 先调用 `tryRoutedTurn`，再按原有条件尝试本地批准路由；现有单轮 `webcli route` 推荐在 `agent.ts` 的模型启动之前准备。正则级联不是单一 matcher：卡片、配置路由、模板、宽泛正则、显式别名、各闸门和失败策略都保持原样。新增逻辑不进入级联内部，也不把追问正则作为决策层的入口条件。

WebCLI 已有版本化多轮 route、结构化调用描述、调用回执和展示登记；它的 `context status` 只给脱敏状态，不能恢复显示映射。Agent 的普通 Shell 路径也没有可用的可信回执；不能用命令文字、模型输出或状态查询伪造它。

## Goals / Non-Goals

- **目标**：普通桌面聊天在已有路由没答出后，多轮高置信或确定性绑定可替代一次文本 Agent 回复；首句命令推荐与普通降级链路维持原语义。
- **非目标**：覆盖任意话术、历史列表搜索、批量／多步、写操作、导航续跑、客户端澄清管理、跨重启恢复；不扩展 CLI、Shell、Adapter、扩展、发行配置或渠道／定时任务／专属 Bot 行为。

## Decisions

### 1. 路由顺序与单次交接

桌面回合保持既有前置校验、权限、取消及确定性路由顺序；本地批准路由仍按原条件运行。确定性层只要已经答复或已发出可见答复，就结束本轮，避免双答。否则在现有 Agent 路径前尝试多轮；略过、未命中和执行失败都不单独阻挡进入决策层。附件、显式工具／场景、权限等仍按原边界处理，不能用历史快照改写用户显式目标。补偿压缩、预热、取消的请求不启动快捷查询。

无可用桌面展示记录时，保留现有单轮命令推荐 → Agent。存在可用记录时，调用现有 `route --json --context <id> -- <message>`；`unrelated` 包含的 `singleTurnRoute` 继续作推荐，不重复请求。其余非直答结果按本轮状态交 Agent，不重跑一遍单轮 route。给 `streamChat` 透传已经准备好的结果或已尝试标记，复用 `withRoutingContext`，避免 Agent 入口再次触发相同决策。保留现有合法的单轮推荐降级路径，不把推荐或模型选择变成首句的执行权。

### 2. 可信展示证据，只保留进程内关联

后端为普通桌面会话记录 WebCLI context ID 及最近一份可追问展示的消息／回合与快照关联。通过首个后端可观测查询的 `--new-context` 懒创建，之后复用 `--context`；不需要为首句命令推荐创建上下文，不接数据库 schema，也不从历史恢复。关闭开关、会话删除、上下文失效或服务重启后不再使用旧关联。按 work 和 turn 隔离，不能让取消或已结束回合的迟到回执重新开通直答。

给桌面确定性查询的最终业务结果（包括符合条件的本地批准直调）和 Agent 结构化 `weworker_read_query` 显式传递上下文；不在通用执行器里按 workId 隐式覆盖其他调用者，不把探测或中间步骤视为展示来源。处理多个查询时，只有能唯一确认最终展示来源才登记。扩展既有调用执行器提供可选带回执结果，旧调用方仍保持业务字符串返回合同。由后端调用内嵌 CLI，分别读取 stdout 业务结果和 stderr 的 `WEBCLI_CONTEXT` 回执；回执须通过版本、会话、执行及持久化状态校验，与业务输出分开处理。普通 Shell 不传新控制参数、不尝试收集回执。

只登记成功交付的可见正文中可核对的编号与对象。后端渲染可随结果保留行映射；Agent 默认按原序展示，但后端只接受能够从实际回复的编号及原始身份（如论文 ID 或规范链接）唯一核对的列表。不能从数字、摘要或提示词约定推算展示全序；无法验证、混有无法归属的编号或未成功交付，不登记。调用现有 `context display <id> --epoch … --revision … --round … --snapshot … --args <JSON>` 传入实际有序 entityRef、真实完整度和 `delivered: true`；只有登记成功且仍属于同一回合，才更新进程内可直答关联。无须改 Renderer 或把已落库等同于用户已看到。

仅在已登记快照仍对应当前展示时直答；若最新可见列表来自 Shell、没有可靠映射，或当前展示来源无法确定，禁用直答，绝不默默选择更早列表。验证决策引用的 source snapshot 和 display version 与桌面记录一致；WebCLI 继续拥有原有效期、指纹、锁和版本校验。宁可少命中，也不推断用户指代。

### 3. 单步只读执行与回复

仅接受版本和结构有效的 `resolved`（确定性绑定或 WebCLI 已接受的高置信选择）、一个 entityRef、一个调用步骤、与本轮及登记快照一致的关联信息。派发前重新核对当前工作区／站点权限、工具启用状态、只读直调资格、无需确认、参数 schema，及本轮未取消；不把 `executionEligibility` 当成授权。使用结构化 tool 和 args、无 Shell 的 argv 及现有 JSON 业务参数入口（保持字符串、数字等原类型），并传 `--context-decision`、`--context-step`；不执行拼出的命令字符串，不替换绑定参数或重规划。既有 Runner 保持独立。

多轮决策和一次只读调用各最多 3 秒，均服从从开始多轮尝试计起的 8 秒绝对期限。该期限含进程启动、校验、渲染及直答提交前的收尾；只限制新增路径，不计现有正则、单轮推荐或 Agent。这两个阶段都需把超时和回合取消传给所启动的 CLI 进程，过期结果不得提交。纯采集或展示登记失败不重新执行已成功的查询，也不撤回已交付答复；新一轮不得使用尚未确认登记的证据。

只有拿到可展示的业务数据才走现有确定性渲染与桌面消息落库／SSE 完成协议，文本 Agent 调用次数为零。导航、登录提示、失败、超时和不可信／不完整输出不算详情成功；不补跑第二次。若已有可信业务结果而不能直接渲染，用既有有界投影或受控结果引用向 Agent 传递对象、调用状态和结果，避免默认重查；其他情形传必要的本轮决策状态、候选信息或失败原因，由 Agent 继续原流程。工具数据只作不可信参考，不传原始 stderr、内部回执全文或凭证；不注入持久记忆。已提交的答复不能再退回 Agent。

## Risks / Trade-offs

- Agent 没展示可核对的身份或排了其他内容 → 放弃直答；不上模型对账或新卡片。结构化查询路径需验证 arXiv 用例能稳定产生可登记展示。
- 当前 CLI 的自然语言候选通常是焦点或已展示范围，不保证能解析多条列表里任意自然语序的序号。模型验收用只展示一条的自然表达，单独验证模型调用；确定性验收用多条和「查看第二条」。不扩展 CLI 语法。
- WebCLI 窗口、进程启动成本及站点响应可能导致未命中 → 按原链路降级；测试分别证明模拟决策高置信路径和真实服务命中，不预报性能或命中率。

## Migration Plan

无迁移。现有开关开启才进入新增路径；关闭后不采集也不直答，保留正则原链。验证开发态与桌面打包入口均能读取现有协议，不改发行流程。
