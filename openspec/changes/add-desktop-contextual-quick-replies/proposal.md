## Why

普通桌面聊天在现有确定性路由未答出时，通常由文本 Agent 完成查询和追问。对于「查看第二条」这类能可靠绑定到已展示对象的只读追问，可以直接用现有 WebCLI 多轮决策完成这一轮，省掉一次文本 Agent 调用。它是快捷路径，不是替代 Agent 的会话编排器。

## What Changes

- 保留现有正则／确定性路由优先级，包括本地批准路由；筛选略过、未命中或执行失败且未产出可用答复时，再进入决策层。
- 首句和新话题的单轮命令推荐仍只作为本轮参考传给文本 Agent，由 Agent 填参、执行和回复，不按推荐自动调用。
- 在普通桌面聊天内关联后端可信查询回执与实际展示的列表。仅当已有决策能绑定当前已展示的单对象、生成一次完整的只读且无需确认的调用，并取得可展示结果时，后端直接答复。
- 不能直答时，把相关上下文交给现有 Agent；已有可用的查询结果则复用。决策与调用各最多 3 秒，新增快捷路径端到端最多 8 秒，无自动续调或重试。
- 沿用现有 WebCLI 路由开关。不开新设置，不做跨重启恢复、客户端澄清续接或多步执行；不修改外部 Shell 命令、WebCLI 协议、Adapter、扩展或内部发行配置。

## Capabilities

### New Capabilities

- `desktop-contextual-quick-replies`: 普通桌面聊天的可信列表登记、单对象直答和 Agent 降级。

### Modified Capabilities

无。本变更新增桌面消费方，不修改已有 WebCLI 上下文能力合同。

## Impact

- 基线：公开仓 `dev-1.2.1`（评审时 `bc228664`）。依赖已有 `add-webcli-contextual-multi-turn-decisions` 的实现，本变更独立跟踪桌面接线，不把旧验证报告当桌面验收。
- 改动范围：`weworker/backend-ts` 的桌面回合编排、WebCLI 子进程调用与回执消费、结构化只读查询、Agent 单轮上下文接线；复用既有 SSE 和消息格式。不需要数据库迁移或新增依赖。
- 验收使用已有绑定的公开 arXiv Adapter，分别验证确定性序号和真实决策服务高置信两条直答路径。安全工单等未声明对应绑定的内部场景不作为本变更直答验收前提。
