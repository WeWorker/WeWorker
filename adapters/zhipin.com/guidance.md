# BOSS 直聘使用指导

search/detail 用于求职信息；查询城市、经验、学历、薪资、行业、jobType 保持 BOSS 参数语义，不能沿用 51job 城市代码。城市默认北京只是站点参数默认值，用户指定其他城市时必须显式传 city。detail 的 ID 来自 search 返回链接。

chatlist/chatmsg 按 side 选择求职端或招聘端；其他命令是否仅招聘端以描述和服务端身份校验为准。先读列表取得 encryptUid/encryptJobId，再查看候选人或聊天。加密 UID、数字 UID、职位 ID 各有用途，不互相替代。whoami 当前仅验证本地 Cookie 标记，不证明服务器登录有效。

stats 的 sampled_chats 仅第一页联系人按职位名称分组的样本数，重名职位可混合，不能当职位总聊天数。total_chats 缺失为 null；总计行是账号好友数口径。search 先建立对应查询页面，再使用页面主世界请求官方职位接口，逐页显式传递关键词、城市和筛选条件；page 为起始页，limit 为返回上限。按职位 ID 去重；不足 limit 不等于全站没有更多职位，不能宣称已遍历。调用有时间预算，超出时缩小 limit 并指定 page，不盲目重复。

send/batchgreet 等写操作需要具体目标和文案的用户确认。当前 UI 还必须能核验激活会话的数字 UID，否则拒绝发送；点击候选人不等于已确认收件人。“已点击发送”不等于送达。批量招呼可能部分执行，失败后先逐个核对，不能重放整批。

## 调用与证据

普通参数使用 --key=value；复杂结构才使用 JSON。只调用本 Skill 当前 manifest 列出的命令。用户说“第二个”“刚才那条”时保留上一轮实际 ID 和链接，不重新取列表位置代替实体。相对日期按当前日期和用户时区换算并写出实际日期；关键缺参先追问，不能从站点默认值猜用户选择。

只读页面导航由宿主在一次调用中续执行。登录和验证码由用户在连接扩展的同一浏览器中完成；login 只打开官方页并结束，不会等待 timeout 秒或宣称已经登录。whoami 不等于完整登录验收。当前要求、当前 Skill 和本轮证据优先于历史失败记忆。临时失败不能变成永久跳过工具的规则。

接口失败、验证页、字段缺失、页面空状态与真正无结果须区分。字段为 null 或空串表示未知，不补猜。返回列表不等于全站完整结果；limit 是上限。失败保留 trace，不重复相同参数盲目重试，不用降级查询宣称原命令通过。

仅在用户要求执行且目标、内容明确时提交写操作；参数不清楚时先澄清。导航准备不等于业务操作完成，写操作不得自动重放。超时后先核查站点状态，不能直接重发。

## 多轮结果与后续动作

recommend/resume 保留加密候选人 UID，后续简历、聊天、标签、联系方式、面试与发送动作各自绑定参数；缺少文案/标签/时间等显式输入时续接澄清。joblist 的加密职位 ID 用于职位详情、统计和职位聊天。chatlist 返回实际 identity_side；auto/geek 查询仅公开安全的聊天读取，指定 side=boss 才公开招聘端候选人写动作。chatmsg side=boss 可按原始 query.uid 回复；auto/geek 不映射到招聘端 send。stats 总计行的 followup_job_id=null，禁止将其变成全量聊天查询。whoami 仅本地登录诊断。greet 保留数字收件人校验，点击发送不证明送达。
