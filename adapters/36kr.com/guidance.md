# 36氪使用指导

hot 有四类榜单：catalog（热门资讯聚合页，默认）走固定路由；renqi（人气榜）、zonghe（综合榜）、shoucang（收藏榜）按当天 UTC+8 日期访问各自官方榜单页。请求哪类就必须读哪类的页面，不能用其他榜单的结果冒充；页面标题必须与请求的榜单名一致，否则按结构错误失败。结果只取经过真实 DOM 核验的榜单区域（`.article-list` 榜单行 / `.list-section-wrapper` 分区），全页其他 `/p/` 链接（导航、侧栏推荐）一律不算结果。catalog 聚合页实际由人气榜/综合榜/收藏榜三个分区组成，每行的 board/board_url 标注该行真实所属分区与分区入口，不整体冒充为单一榜单；type 表示请求的类型。读取会轮询等待可信区域内出现可解析行：容器先渲染、行后填充的动态页不会被误判为空。榜单页面没有已验证的空态标记，因此不支持空榜判定——区域持续无条目一律按渲染/结构异常报错，不报空结果。区域未就绪、标题不一致、行不可解析分别是不同的结构/渲染错误，都不算成功。返回行中的 type/board/board_url 用于核对实际来源。

news 读取官方 RSS：summary 是描述文本前 120 字符的摘要，不是全文；date 为按标准 RSS pubDate 解析出的完整 ISO 8601 时间，pubDate 缺失或非法时为 null，不猜日期。信封经有界结构校验：根 rss/通道/条目未闭合或结构异常、条目存在但均无可用标题、HTTP 200 返回 HTML，都报解析/接口错误，不算空结果；CDATA 内的伪标记（如描述里的 `<html>` 或假 `<item>` 文字）不算条目也不算错误信封。只有结构合法的通道确实零条目才报空。空标题条目跳过。

search 关键词严格 URL 编码；结果只取结果区域内 `kr-search-result-list-main` 的文章卡片标题链接，无全页回退。页面自带无结果提示（`.kr-search-nodata`）才报空结果；结果区域未就绪、区域在但既无卡片也无提示，分别报渲染/结构错误。当前卡片不暴露日期，date 为空串（不补造）。

article 接受纯数字 ID 或完整官方文章路径 `https://36kr.com|www.36kr.com/p/<纯数字>`（允许尾斜杠、查询与 hash；`/p/123abc`、`/foo/p/123`、外域、带凭据、会丢精度的超长数字一律拒绝），拒绝从混杂字符串里猜数字。正文按来源语义只截取前 800 字符：body 是截断后文本，body_length 是页面提取文本总长，body_truncated 标注是否截断，content_status 说明口径；url 输出规范化为 `https://www.36kr.com/p/<id>`。完整全文无法由本命令获得时应如实告知并给出 url，不能把摘要或截断文本说成全文已完成。

## 调用与证据

普通参数使用 --key=value；复杂结构才使用 JSON。只调用本 Skill 当前 manifest 列出的命令。用户说“第二篇”“刚才那篇”时保留上一轮真实文章 URL/ID，不重新取列表位置代替实体。相对日期按当前日期和用户时区换算并写出实际日期。

hot/news/search/article 全部为只读命令，无写操作、无确认门；页面命令由宿主在一次调用内自动开页并续执行。若页面出现验证码/安全验证会明确报错，需用户在连接扩展的同一浏览器完成后重试。

接口 HTTP 错误、重定向、空结果、渲染超时、字段缺失各自明确区分；字段为 null 或空串表示未知或缺失，不补猜。返回列表不等于全站完整结果，limit 是上限。失败保留 trace，不重复相同参数盲目重试，不用降级查询宣称原命令通过。本轮证据优先于历史失败记忆；临时失败不能变成永久跳过工具的规则。
