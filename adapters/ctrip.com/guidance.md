# 携程使用指导

## 从用户需求选择命令

- 用户要求往返报价时使用 flight-round，不能因旧版超时记忆直接改成两个 flight 单程；当前版本已支持真实往返组合。仅在本轮对应工具失败后才可解释替代方案，不能将替代方案称为原任务成功。
- 航站楼必须对应方向：departureTerminal 属于出发机场，arrivalTerminal 属于到达机场；兼容字段 terminal 只表示到达航站楼，不能移到出发机场。字段为空时不补猜。

- 普通用户只需表达目的地、日期和偏好，不要求用户提供命令、ID 或机场代码。Agent 根据当前命令定义拆解任务，查询必要信息后组合调用。
- search 是酒店业务城市/地标联想，destination-search 是景点目的地查询，不是景点排名或实时旅游报价。景点列表用 attraction；具体酒店详情用 hotel；按入住日期看酒店用 hotel-search；跟团产品用 tour；机酒自由行产品用 package。cruise 的 port 是出发港，而非目的地。
- “去贵阳玩，查景点和航班”拆成独立查询：先查贵阳城市候选及景点；若缺出发地，询问出发地，不必阻塞景点部分。上下文已明确的信息不要重复询问。

## 地点和实体参数的来源

- attraction.city：先调用 destination-search，按 name 和 region 选择匹配目的地，使用 destinationId。hotelCityId 仅供酒店；例如贵阳 destinationId=33、hotelCityId=38，景点站的 38 却是香港。禁止混用 search/hotel-suggest 的 cityId、景点 id 或上级地区编号。同名候选有歧义时澄清，无匹配时报告映射失败，不猜编号。
- hotel-search.city：优先用 hotel-suggest 查匹配的 City 条目的 cityId。不要把 Hotel 的 id、商圈 id、车站 id 当成城市 ID，也不要假定不同业务城市编号永远通用。
- hotel.id：取 hotel-search 返回的 hotelId、hotel-suggest 中 Hotel 条目的 id，或用户提供的携程酒店详情链接 hotelid。品牌名不能唯一确定酒店；核对城市和分店。“刚才第二家”引用上一轮实际结果，并保留对应 ID，不能重新查询后直接取新的第二条。
- train 的 from/to 可以是城市或具体车站名称；上海不等于上海虹桥，也不等于上海松江。保留用户指定的站点；城市查询展示实际出发和到达车站。bus/ferry 用城市查询，结果中再核对车站或港口；不虚构站点筛选参数。
- flight/flight-round 使用 IATA 城市或机场三字码。不能把 search 的数字 cityId 填进去。当前没有专门的航班代码查询命令；代码不确定时使用可核验的来源，不凭读音拼代码。城市与机场范围不同（如北京城市 BJS 与首都机场 PEK）；用户没有限定机场时不要擅自缩小范围。同城机场或出发地歧义影响结果时再澄清。
- cruise 内部查询港口索引，Agent 传名称即可，不维护手写港口代码表。

## 日期、必要信息与用户偏好

- 根据本次请求的当前日期、用户时区解释明天、下周五等，最终回答写出实际日期。“国庆”“周末”“最近”有影响行程的歧义时澄清；不沿用测试日期或把“最近”自动解释成最低价。
- 酒店必须有入住/离店日期；“住两晚”从入住日期加两天。往返必须有出发/返回日期。交通缺出发地或出发日期时询问，不从机器位置猜用户行程。用户明确指定展示条数时传对应 limit（例如“列三个”传 limit=3）；未指定时可用默认值，无需反复提问。
- 当前航班固定 1 名成人、无儿童/婴儿、全舱位；酒店无人数/房间数/早餐/可退筛选参数；tour/package 无日期、人数和出发地报价筛选；cruise 无日期筛选。遇到“两大一小”等要求，说明当前结果是参考，不能声称已按这些条件报价。
- 预算、时段、高铁、设施等可在有对应字段的已返回结果中筛选，但须说明覆盖范围；缺少距离或位置证据时不声称“离景点最近”。如现有工具不支持关键条件，明确缺口，不悄悄丢掉用户条件。

## 执行与错误处理

- search、destination-search、hotel-suggest、whoami 在后台执行，无需先打开携程页面。公共查询不要求先登录。
- 页面命令由宿主在一次调用中完成开页、导航、等待及读取，不向用户转述内部导航步骤，不要求用户手工重复同一条命令。同一页面的任务由宿主串行执行，避免互相跳转。
- 登录/验证码需要用户在连接扩展的浏览器中完成后再继续；whoami 识别本地登录标记，不是服务器会话有效性的保证。login 仅打开官方登录页，不代用户填写凭据；遵守当前 manifest 确认策略。
- 指定命令验收失败时如实标记该命令未通过，不用其他命令的降级结果标记成功。一般查询若提供替代方案，也必须明确原请求失败及替代报价口径。
- 页面读取失败、捕获未完成、超时和未登录不能当作“没有结果”。只在站点明确无结果时解释为无结果。不要无限重试或自动改城市、日期来制造成功；保留错误与 trace 供排查。

## 结果解释与行动边界

- limit 是返回上限，不是保证条数或翻页。酒店只读 SSR 首屏（通常约 13 条），景点/度假产品也非全站穷举；增大 limit 不代表已经遍历全部结果。rank 只是本次返回序号，不是官方质量排名。返回 20 条只能说“本次返回 20 条”，禁止称“当天共 20 班”或据此断言当天最早、全站最低价。
- 单程航班当前先排未识别到换乘的行程，再按价格、出发时间排序，第一条不一定是全站最便宜或最早。connecting=false 只表示未识别到换乘，不保证途中无经停；stopCount 为明确数字时可说明经停次数，stops 展示已取得的经停地点；stopCount=null 时是未知，不能把 stops=[] 当成无经停。没有明确的经停字段证据时，禁止称“直飞”“不停站”，只能展示航班与起降信息。用 connecting/segments 和完整日期字段判断中转及跨日，不只比较 HH:mm；当地时间不带时区时，不自行计算跨时区飞行时长。
- 往返航班返回同一报价的 outbound 去程与 return 返程，两程都应展示日期、机场和经停信息。priceScope=round_trip_one_adult 是 1 成人往返组合报价，非单程价；taxesIncluded=null 表示未确认税费是否包含。不要把它说成已经出票或锁价。火车 fromPrice 是起价；未开售、预约抢票不等于有余票。页面“订票”按钮不保证最终成交时仍有库存。
- 酒店设施不等于已包含在房价，入住政策不等于每种房型的取消政策。酒店/旅游/邮轮展示价不应自动解释为多人的总价、每晚含税价或最终结算价。货币、价格口径不清楚时如实说明。列表 price 未明确标注计价单位时，不擅自标成“每晚”或计算两晚总价。缺少具体房型证据时只说“不能确认”，不推测“含早可退通常更贵”“起价大概率不适用”。星级/钻级性质没有明确字段时也不自行补全。
- null 表示未取得，不是零、免费、没有设施或无票。缺少字段不编造；结合名称、链接、日期、实际车站/机场向用户呈现可核对结果。
- 当前包不支持购票、酒店预订、支付、退改签。用户说“帮我订”时先说明可查询与比较的范围，不能把查询成功说成预订成功。

- tour/package 的 departureCityId 是站点自动选择的出发城市上下文，不是用户已确认的出发地；不得据此声称满足从北京或其他指定城市出发。列表价格不是指定出行日期和人数的确定报价。导航超限本身不能证明暂态环境故障；没有诊断证据时说明原因待查，不许承诺稍后自然恢复。trace ID 必须逐字复制，查不到时先核对是否抄错。

- package 按产品卡片 productType 筛选明确标为自由行/目的地自由行的条目，私家团、跟团游不能当作自由行。当前页少于 limit 时只展示实际条数，明确当前页范围；不换类型凑数、不把不足三条解释为全站只有这些。departureCity 是卡片原文，departureCityId 是页面上下文，两者都不是用户确认的出发地。

- ferry 若报告页面“无航次信息”，仅说明当前站点查询未取得列表；该页面也可能由上游请求失败触发，不能宣称航线不存在、当天停航或无票。不要以相同参数自动重复重试，也不要记为永久不支持。

## 多轮结果与后续动作

search/hotel-suggest 区分 City、Hotel 与 Station 等建议类型；只有 Hotel ID 能打开酒店详情，只有 City 的 hotelCityId 能进入酒店查询。destination-search 的 destinationId 用于景点，hotelCityId 用于酒店，不能混用。hotel-search 返回的酒店 ID 可直接查看详情；缺入住/退房日期时显式补参。当前没有选定航班/车次/旅游产品的预订或付款命令，不从报价列表推导交易动作。
