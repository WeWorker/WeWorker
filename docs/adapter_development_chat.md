# 在 WeWorker 对话中开发 Adapter

## 快捷入口

1. 打开网站探索agent，选中一次成功探索，点击 **到WeWorker中开发**。
2. 在目标选择弹窗中选择或新建目标 Adapter 和 Tool，然后点击 **选择并打开对话**。已有归属的探索限定为其原目标；独立探索可选择允许当前站点的 Adapter。
3. WeWorker 打开一个新的普通对话，输入框自动带上开发提示词和 `input.json` 文件附件。检查或修改提示词后，点击 **发送**，由对话底层 Agent 开始开发。

点击快捷入口只准备对话，不启动探索侧模型、不发送消息、不修改开发槽位、不安装 Adapter。它不要求配置探索侧开发模型；发送后的模型调用使用普通对话的配置。未保存代码应先保存或放弃。服务不可用、来源归属不符或输入准备失败时保留当前页面，不覆盖已有对话草稿。

## 输入与执行

`input.json` 是本次交接时的输入快照，包含选定的目标 `toolkit`、`tool`、来源探索和功能目标。探索页入口仅基于当前探索，`base_slot` 与调试证据为空，不会在交接时清空或覆盖当前槽位。「回放」按钮位于主操作栏的「到WeWorker中开发」之后；网站探索agent只展示探索功能，不再提供「探索 / 开发」页签、站内开发页或「转为开发」入口。目标选择仅用于把探索结果交给 WeWorker 对话开发。

宿主后端将文件写入新对话的独立工作区；附件通过普通对话的文件引用链路传给 Agent，而不是只在提示词里写一个不可读取的外部路径。网站探索服务只返回输入数据，不直接访问或写入对话目录。每次成功准备使用独立目录，不覆盖之前的 `input.json`。

预填提示词仅负责指定输入和引导读取 Skill：

> 请读取附件 input.json，运行 `webcli skills read adapter-development`，并按照该 Skill 开发和调试 Adapter。

开发流程、提交契约、安全约束、调试和正式应用确认统一由 `adapter-development` Skill 维护，不在预填提示词中重复。

开发后的候选代码、调试和正式安装继续使用现有 WebCLI / 网站探索agent / 宿主 Adapter 安装链路，不引入第二套运行器或兼容转换。

## 接口边界

- Renderer 调用宿主 `POST /api/website-exploration/toolkits/:id/tools/:toolId/development/chat`。
- 宿主核对受管探索服务实例后，调用只读快照接口 `POST /api/toolkits/:id/tools/:toolId/development/input`，携带实例身份头。
- 接口只接受开发指令、来源探索 ID、调试证据 ID 和是否仅基于探索，不接受任意源文件路径、目标目录或服务 URL。
- 初次开发必须有成功且归属正确的探索；继续开发可以仅使用当前槽位。调试证据必须同时匹配 Toolkit 与 Tool。

对话草稿遵循现有客户端的内存草稿机制；本入口不增加草稿跨应用重启恢复能力。实际文件和对话记录持久保留，关闭或重启应用不会自动发送。
