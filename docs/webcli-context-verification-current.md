# WebCLI 多轮决策验证

本报告以公开源码为范围。源代码版本 `e8b77b8c`；已合并基线 `e3b7380f`。可以提交PR进入人工验收；真实接入与业务验收未冒充完成。

## 实现链路

原客户端第一轮：正则路由命中则执行；未命中调用 `webcli route` 推荐命令或站点，再把结果交给文本Agent。此次增加的是route对已有查询结果的多轮决策，继续作为Agent执行前的辅助。

1. `route/call --new-context` 自动生成UUID；后续传 `--context <id>`。
2. 查询通过各自Runner执行，Adapter声明返回对象、后续命令及参数映射。
3. CLI保存最多三轮的有界摘要；Agent登记真实展示顺序。
4. “查看第二条”直接得到对应对象的调用步骤；缺参澄清，歧义或复杂请求交接。
5. Agent调用 `webcli call` 执行步骤；写动作先记录派发事实，结果未知时阻止重放。

route不代替Agent执行命令，也不证明业务成功。降低文本模型耗时是目标，尚未测得真实模型收益。

## 尚未验证与限制

- 真实网站写入、消息送达、发票实际上传和下载落盘：按用户要求后置，mock成功不代表这些动作已成功。
- 真实决策模型的准确率、耗时、token和费用收益，以及当前WeWorker客户端展示/澄清接入：实现后验收。
- 原部署资产需在受控环境独立适配，不能用33个公开包代替；公开PR不导入非公开资产。
- 89条写命令并未穷举所有真实DOM分支；当前测试重点是多轮决策、对象绑定和派发边界。
- 嵌入式宿主context当前返回 `context_host_unsupported`；普通宿主调用不受影响。
- HTML浏览器视觉验收未完成：浏览器工具导航报错；结构检查不能替代视觉检查。
