# API 自动探索优化与验证

## 本次范围

本次 PR 从 `origin/develop` 的 `783e6dbc` 整理，分支为 `codex/api-exploration-optimization`。迁入 API 探索修复和默认生成优化，不包含演示集成分支的模型配置、机器人、导航、版本升级或构建配置变更。

默认“生成并验证”使用 `auto` 模式：

- 从已捕获、已回放验证且被明确选中的只读目标直接生成草稿，完成静态及全部目标的页面执行验证；正常生成阶段不调用模型。
- 具体草稿或输出映射错误最多触发一次局部模型修复，只允许修改本轮新增的目标查询命令。模型调用阶段最多 60 秒，后续页面验证另计。
- 保留原失败、旧草稿和修订，修复后再次验证全部原目标。不允许删除目标、跳过执行或标为不可验证来取得通过状态。
- 页面、登录、网络、权限及证据不足不交给模型修；页面恢复继续原草稿，一次修复预算不会重置。
- 模型超时或用户取消时停止本任务拥有的模型 Worker，迟到响应不得改写草稿；不终止未知进程。
- 复杂参数和多接口任务可显式选择“智能生成”；显式 `quick` 保持完全不调用模型。

探索首条上下文预装结构化证据及必要指引，图标/字体 JSON 不占模型候选视图。模型通过 `finish_api_exploration` 选择覆盖目标的已验证只读接口，选择先持久化，再停止分析。只验证搜索建议、配置或推荐接口不能算完成视频搜索目标。模型分析最多 180 秒，不含此前被动捕获；超时保留证据并标记未完成，拒绝迟到工具更新。

## 一并迁入的依赖修复

- 区分录制动作和被动列表的候选索引，生成计划与实际产物保持一致；成功验证后直接结束编排。
- 输出断言识别生成 fetch 包装层，正常业务内容中的登录、验证码或 HTML 字样不会单独触发认证失败；真实认证错误、HTML、敏感输出及业务断言仍拒绝。
- 补采时核对原捕获契约，保留仍匹配的成功回放；不把截断捕获与完整回放的结构差异当作来源变化。
- 目标子域归属已有站点包时增量生成，保留旧命令、元数据和文件字节；静态、预览及安装核对同一基线摘要，不放宽域名和权限确认。
- 保留 `keyword` 参数名，增量验证环境对齐页面全局和实际探索 host，刷新 RPC 使用有界 60 秒期限。
- 显式智能流程模型超时后，仅完整只读草稿可重新静态检查并执行全部目标；成功仍保留 `AI_WORKER_TIMEOUT` 及恢复标记，不计模型正常返回。

以下来自演示集成分支 `codex/demo-1.1.0` 的 `6993ac07` 及其前置修复，模型为 glm-5.3。脚本调用正式 Coordinator、Bridge 和产品扩展，均使用既有 Chrome 会话；这些是迁入前的证据，不等于本 PR 分支完整客户端重新验收。

| --- | --- |
| 新任务自主探索 → 默认生成 | 探索约 63.400 秒；总计约 71.439 秒到安装确认；生成模型调用 0、静态及页面执行 1/1 通过、跳过 0 |
| 上述产物隔离安装与调用 | 安装和刷新通过；保留旧 9 命令；仅调用本轮新增工具，python/javascript 各 3 次及“登录教程”1 次，7/7 返回 20 条有效视频行，单次 3.552–3.893 秒 |
| 第二个新任务自主探索 → 默认生成 | 探索约 78.656 秒，总计约 85.731 秒到安装确认；生成模型调用 0、静态及页面执行 1/1 通过；未安装 |
| 真实模型受控修复 | example.com 虚构接口、注入丢失返回值故障；一次模型调用后静态及实际函数执行通过，总计 17.712 秒；没有真实网站或产品预览 |

两轮新任务均未复用前轮探索记忆。耗时由脚本轮询观测，不能视作精确性能基准。标题包含词分别为 python 20/20、javascript 18/20、“登录教程”6/20，未人工逐个打开视频，不代表完整语义质量；关键词尚未声明必填，不代表完整参数契约。

失败同样保留：早期一轮约 114.071 秒但未捕获目标搜索接口，仅建议接口 verified；另一轮旧 Bridge 丢弃 auto 并进入旧智能流程后失败。此前智能超时恢复约 314.860 秒，使用不同证据起点与流程，不能与上述新任务直接计算性能倍数。原始诊断、真实响应、Cookie 和凭据只保留在本地，不提交。
