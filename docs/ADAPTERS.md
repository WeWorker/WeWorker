## 状态定义

| 状态 | 判定标准 |
| --- | --- |
| 已实现 | 仓库中存在可加载的 Adapter、manifest 和必要运行代码，并有明确的当前能力说明 |
| 开发中 | 已有正在开发的实现，但尚未达到可供用户稳定使用的标准 |
| 规划中 | 保留在产品路线图中，当前仓库没有可用实现 |

`默认打包` 与 `默认启用` 是独立属性：已实现的 Adapter 也可能因兼容性、认证方式或发布策略而暂不进入默认安装包。

## 能力与风险边界

- Adapter 依赖目标网站当前页面和接口，网站更新后可能需要同步维护。
- “已实现”表示仓库存在实现，不保证目标网站在所有账号、地区和时间均保持兼容。
- 需要认证的 Adapter 使用浏览器现有登录状态，不应在代码、Issue 或测试数据中保存真实账号、Cookie 或 Token。
- 发送、发布、下单、支付、投递等具有外部影响的操作必须提供清晰的用户确认。
- 用户需要遵守目标网站的服务协议、自动化规则和所在地区适用法律。

## 状态更新规则

新增或推进 Adapter 的 Pull Request 应同时完成：

1. 添加或更新 `extension/adapters/<adapter-id>/` 下的 manifest、运行代码和必要说明。
2. 更新 `extension/adapters/index.json`。
3. 明确是否加入 `weworker/build-profile.json` 的默认安装包。
4. 添加聚焦自动化测试，并使用脱敏的示例数据。
5. 在本文件中更新状态、能力和发布说明。
6. 如果功能对用户可见，在根 `CHANGELOG.md` 的下一版本中记录变化。

Adapter 开发和调试方式见 [浏览器扩展文档](../extension/README.md)。
