# Adapter 后续动作审查

范围为本仓库33个公开包、334条命令。171条查询已有动作映射，89条写命令单独统计；其余74条查询按用途分为以下三类。逐条判断见 [完整清单](context-adapter-followups.json)，原始声明、目标命令和包指纹见 [命令清单](context-adapter-inventory.json)。

|分类|查询数|处理|
|---|---:|---|
|登录、账号和导航诊断|23|不生成对象动作；需要业务对象时重新执行对应查询|
|当前读取结果的终点|17|已返回资料、正文或指标；本次不为数据行发明操作|
|缺少下游能力|34|当前包没有合法目标命令；要继续下钻必须开发新能力|

这些数字是查询命令数，不是网站数、测试数或用户任务数。同一查询可以包含多个动作，写命令也可能独立调用，因此三类数不能推导执行覆盖率。

## 后续开发顺序

|顺序|涉及查询|需要新增的能力|当前多轮行为|
|---|---|---|---|
|优先补只读下钻|什么值得买搜索、掘金候选、抖音公开搜索/用户作品、头条公开内容、雪球帖子|可靠对象ID、详情处理器及其实际返回验证；掘金还需先实现真实候选查询|交接Agent，不把公共对象送入创作者写命令|
|优先补部分缺失动作|Gitee搜索/趋势已有所有者资料动作，但没有仓库详情|仓库详情处理器及精确仓库身份验证|“查看所有者第二条”可执行；“查看第二条”交接，不偷换成所有者资料|
|按产品需求补齐|携程行程/产品、12306订单和乘客、京东订单、点评商家、1688店铺|对应详情、精确对象范围；预订/取消/支付另需业务能力|不拼造详情或交易命令|
|按使用频率补齐|B站评论、知乎想法、抖音草稿/合集/活动/地点、36氪全文|对象专用读取或操作；不能复用不同对象类型的ID|保留当前结果，明确能力不可用|
|需要文件功能时补齐|1688媒体链接|真实文件保存接口及落盘结果核验|仅返回媒体URL，不声称已下载|

以上是能力扩展顺序，当前实现没有把它们包装成已完成的映射。34仅统计无动作查询中的缺口，有映射查询也可能缺少其他动作，Gitee即为一例。现有公开包范围内没有等待用户提供接口才能修复的映射阻塞；这些工作可以由开发继续推进，但新增下游业务能力需要作为后续变更验证。

原部署资产需在受控环境按当前运行时独立适配，本公开包清单和测试不能代表它们。WeWorker客户端、真实模型收益及真实站点写入按用户要求放在实现后的验收。

## 测试边界

清单扫描证明包结构、声明及动作目标能通过校验；实际Adapter源码加mock页面/网络证明代表链路；独立CLI进程加mock Bridge证明会话和派发协议。所有公开包均纳入扫描，业务处理器覆盖情况以测试报告中的具体场景为准，不声称89条写命令的全部真实DOM分支都已认证。
