# 自动探索生成工具开发者体验说明

本文档面向内部开发者体验自动探索能力。该能力当前不是公开功能，默认隐藏；需要在插件侧开启开发者模式后使用。

## 界面速览

自动探索主要涉及 5 个界面：

1. 插件 `使用` 首页：连续点击底部版本号 5 次，开启开发者模式。
2. `生成` 标签页：点击 `开始探索`，对当前浏览器页面进行探索。
3. 探索结果页：查看候选 API 列表、接口描述和推荐策略。
4. 录制操作页：可选。手动触发一次业务接口，补充生成 adapter 所需的操作样本。
5. `配置` 标签页：配置大模型信息，并测试连通性。

## 功能范围

自动探索流程用于把一个网站从“暂无适配器”推进到“可在插件使用页调用工具”的初版状态：

1. 探索网站：分析当前页面、页面结构、关键接口和候选业务 API。
2. 录制操作：可选。开发者在页面上真实执行一次业务动作，插件将完整请求转换为不含捕获值的结构证据；截断请求只记为 opaque。
3. 生成工具：只读能力可快速生成；写能力必须由 Agent 按结构证据编写并通过 mock 验证，生成后才可进入发布确认。

当前定位是开发者体验版，适合快速验证网站可自动生成哪些工具；生成结果通常仍需要开发者复核和二次优化。

## 使用前准备

### 1. 启动 WebCLI Bridge

插件生成工具、保存探索结果、AI 配置读写都依赖本地 Bridge。

```bash
node webcli/index.js service start -d
node webcli/index.js service status
```

如果插件左下角显示 `Bridge 未连接`，先重启 Bridge：

```bash
node webcli/index.js service stop
node webcli/index.js service start -d
```

后台日志位置通常会在启动命令输出中显示，例如：

```text
~/.webcli/service.log
```

### 2. 安装或重新加载插件

在 Chrome 打开 `chrome://extensions/`：

- 开启“开发者模式”。
- 点击“加载已解压的扩展程序”。
- 选择仓库里的 `extension/` 目录。
- 代码有更新时，点击扩展卡片上的“重新加载”。

重新加载扩展后，建议刷新目标网站页面，确保 adapter 和 content script 重新注入。

### 3. 登录目标网站

自动探索会基于当前 Chrome Tab 执行。请先打开目标网站，并完成登录。
如果后续要录制操作，请确认当前页面已经处在适合操作的位置。

## 开启隐藏入口

自动探索入口当前默认隐藏。

1. 打开插件 Side Panel。
2. 找到底部版本号，例如 `v0.x.x`。
3. 在 1 秒内连续点击版本号 5 次。
4. 出现 toast `已开启开发者模式` 后，顶部会显示 `生成` 和 `配置` 两个标签页。

再次连续点击 5 次版本号会关闭开发者模式。

注意：发布版初始化时会强制隐藏开发者入口，即使旧版本曾经保存过开启状态，也需要重新点击 5 次版本号。

![插件首页，连续点击底部版本号 5 次开启开发者模式](./assets/auto-exploration/01-enable-developer-mode.png)

图 1：插件首页。底部右侧版本号是隐藏入口，连续点击 5 次后进入开发者模式。

## 配置 AI

进入 `配置` 标签页：

1. 选择厂家：`Anthropic`、`OpenAI`、`DeepSeek`、`智谱`、`千问` 或 `自定义`。
2. 填写 `API Key`、`Base URL`、`Model`。
3. 点击 `测试配置`，确认连通性。
4. 点击 `保存配置`。

配置会写入本地：

```text
~/.webcli/config.json
```

探索和录制结果会优先走 AI 分析；如果 AI 不可用，会回退到规则分析，但结果质量会明显下降。

![配置页，填写大模型 API Key、Base URL、Model 并测试配置](./assets/auto-exploration/05-model-config.png)

图 5：配置页。填写自己的大模型服务信息后，先点击 `测试配置` 验证连通性，再点击 `保存配置`。

## 三段式使用流程

### Step 1：探索网站

1. 打开目标网站的目标页面。
2. 打开插件 Side Panel，进入 `生成` 标签页。
3. 点击 `开始探索`。
4. 插件会刷新当前页面并被动捕获页面初始化阶段的 Fetch/XHR；等待探索完成后，查看候选 API、接口说明和页面分析结果。
5. 点击 `下一步：录制操作`。

建议直接在你希望生成工具的业务页面上开始探索，不要在首页或无关页面上探索。

![生成标签页，点击开始探索当前网站](./assets/auto-exploration/02-generate-start-exploration.png)

图 2：生成页的探索入口。点击 `开始探索` 后，插件会刷新当前 Tab，等待页面数据加载稳定，并分析初始化阶段捕获到的关键请求和可复用数据。默认探索不会填写搜索框、点击分页或进入详情。

![探索结果页，展示候选 API 列表和接口描述](./assets/auto-exploration/03-exploration-results.png)

图 3：探索结果页。这里会展示推荐策略、候选 API 列表和每个接口的用途描述，开发者可据此判断是否需要继续录制操作。

### Step 2：录制操作

录制是可选步骤，也是发现条件查询和交互接口的唯一入口：

- 如果页面初始化阶段捕获到的列表、汇总等查询接口已经满足需求，可以点击 `跳过，去生成工具`。
- 如果需要搜索、筛选、翻页或查看详情，请录制一次对应的手动操作；这些交互不再由默认探索自动触发。
- 如果需要提交、预订、取消、审批等写操作，建议录制一次真实操作。

录制写操作时：

1. 填写 `操作名称`，例如 `预订会议室`、`取消预订`、`查询订单`。
2. 点击 `开始录制操作`。
3. 回到网页执行一次真实业务操作。
4. 操作完成后，点击 `结束录制` 或 `结束捕获`。
5. 等待分析完成。

注意：录制默认是“记录并放行真实请求”，也就是你的页面操作会真的提交到目标系统。请优先使用测试环境或低风险数据。

录制结束后请检查请求完整性。若界面或生成任务提示 body 为 truncated/opaque，不要从可见前缀猜测字段，也不要重复使用旧 payload；应调整捕获时机后重新录制完整请求。持久化证据只保留字段名、嵌套类型和完整性状态，不保留本次操作的业务值。

如果需要录制多个动作，完成一次录制后，使用结果区里的“继续录制下一个动作”入口，或清空当前结果后重新录制。

![录制操作页，填写操作名称后开始录制或跳过生成工具](./assets/auto-exploration/04-record-operation.png)

图 4：录制操作页。如果需要手动触发接口，先填写 `操作名称`，再点击 `开始录制操作`，随后回到页面执行真实操作；操作完成后点击 `结束录制` 或 `结束捕获`。如果不需要录制，可以直接点击 `跳过，去生成工具`。

### Step 3：生成工具

1. 进入 `生成工具` 步骤。
2. 点击 `智能生成` 启动默认的 Agent Harness 生成闭环；`快速生成` 只用于 read-only 候选。
3. 插件会自动保存本次探索结果。智能生成会制定计划，在独立草稿目录写入，执行静态验证，并在当前已登录页面临时加载草稿验证只读工具。
4. 智能生成停在“等待发布”后，确认工具和验证结果并点击 `确认发布`。
5. 发布成功后，回到 `使用` 标签页查看工具列表。

生成策略：

- `智能生成`：使用受限 Tool Loop 制定计划，在独立草稿目录由 Agent 编写语义工具、验证并按需自动修正，确认后才发布。
- `快速生成`：只生成 read-only 工具；写候选不会由抓包样本机械生成。
- 写工具必须声明 `access: write` 并带确认门；未确认调用必须零 I/O，确认调用需通过精确 method/URL/body 的 focused mock，并覆盖业务成功与失败。页面 Preview 不执行真实写入。
- 写请求 body 截断、opaque，或字段归属不明确时，任务会进入“需要补充信息”，不得标记为“无法验证”后继续发布。
- 同名工具会被更新。
- 非重名的已有工具会保留。
- 已存在人工维护的 `SKILL.md` 时，自动生成的新 skill 草稿会写入 `SKILL.generated.md`，避免覆盖人工优化内容。

如果生成后“使用”页没有刷新出工具，先刷新目标网站页面；仍不生效时，重新加载插件并重启 Bridge。

## 生成产物位置

生成式 adapter 通常写入：

```text
extension/adapters/<site>/
├── manifest.json
├── SKILL.md 或 SKILL.generated.md
├── WEBCLI_KNOWLEDGE.md
├── WEBCLI_KNOWLEDGE.json
└── webcli-generated/
    ├── shared/
    ├── tools/
    └── <site>.site-entry.generated.js
```

其中：

- `manifest.json`：adapter 基础信息、匹配域名、support files。
- `webcli-generated/tools/*.generated.js`：生成出的工具实现。
- `webcli-generated/shared/*.runtime.generated.js`：工具共享运行时。
- `SKILL.md` / `SKILL.generated.md`：给 Agent 使用的工具说明。
- `WEBCLI_KNOWLEDGE.*`：探索和录制沉淀的安全接口结构、字段类型、完整性和已知问题；不保存原始 request body 或捕获业务值。

## 验证生成结果

### 插件内验证

1. 刷新目标网站页面。
2. 打开插件 `使用` 标签页。
3. 点击生成出的工具。
4. 在弹窗里填写参数并执行。
5. 检查返回结果是否符合预期。

### WeWorker 客户端验证

生成成功后，Bridge 会通知正在运行的 WeWorker 清除 adapter 缓存并安装新网站 Skill，不需要重启客户端。保持目标网站已打开且处于登录状态，然后直接在 WeWorker 中发送自然语言业务指令，例如：

```text
打开企业待办平台，先检查登录状态，再查询我的待审批任务，返回前 5 条。
```

如果生成后立刻发送指令，WeWorker 会等待本次 Skill 热加载完成，再启动对话任务，避免出现新网站 Skill 尚未安装的竞态。

### 命令行验证

查看 adapter 工具列表：

```bash
node webcli/index.js adapter info <site>
```

调用工具：

```bash
node webcli/index.js call <site>.<tool_name> --args '{"key":"value"}'
```

查看 skill：

```bash
node webcli/index.js adapter skill <site>
node webcli/index.js adapter skill <site> --generated
```

查看探索知识：

```bash
node webcli/index.js adapter knowledge <site>
node webcli/index.js adapter knowledge <site> --json
```

## 常见问题

### 插件显示 Bridge 未连接

先确认服务状态：

```bash
node webcli/index.js service status
```

如果未运行，启动服务；如果状态异常，重启服务并重新加载插件。

### AI 配置测试超时

优先检查：

- Bridge 是否连接。
- `Base URL` 是否正确。
- `Model` 是否真实可用。
- API Key 是否有权限。
- Bridge 日志里是否有模型响应解析错误。

### 探索结果质量不稳定

建议：

- 在具体业务页面上探索，不要在首页探索。
- 先完成登录和必要筛选。
- 对写操作使用录制步骤补充上下文。
- 确保 AI 配置可用，否则会回退规则分析。

### 生成成功但工具列表没变化

按顺序处理：

1. 刷新目标网站页面。
2. 重新打开插件 Side Panel。
3. 重新加载 Chrome 扩展。
4. 重启 WebCLI Bridge。

### 录制操作没有捕获到目标接口

可尝试：

- 延长超时时间。
- 在“匹配关键词”里填接口路径关键字。
- 确认操作确实触发了网络请求。
- 避免在点击 `开始录制操作` 之前就完成了业务请求。

## 体验反馈建议

开发者体验时建议记录以下信息：

- 目标网站域名和页面 URL。
- 使用的是正式环境还是测试环境。
- 是否配置 AI，以及模型名称。
- 探索结果是否识别出关键接口。
- 录制操作是否捕获到预期请求。
- 生成出的工具名称、参数、描述是否可理解。
- 插件“使用”页能否直接调用成功。
- 生成文件里是否有明显错误或需要人工修正的地方。
- Bridge 日志和失败 trace id。

## 当前限制

- 该能力仍是开发者体验版，不建议直接面向普通用户开放。
- 写操作录制会放行真实请求，必须注意测试环境和数据安全。
- 自动生成工具不保证一次生成即达到生产质量。
- 对复杂登录、验证码、多步骤动态表单、强业务校验的页面，仍可能需要人工优化。
- 生成结果依赖探索页面和录制样本；样本不完整时，工具参数和字段映射可能不完整。
