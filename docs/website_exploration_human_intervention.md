# 网站探索中的人工介入

Adapter工坊的网站探索可以由模型自主判断何时需要用户帮助。登录、验证码、表单校验失败、缺少必要信息和目标不明确是常见例子，不是允许暂停的完整清单。

模型必须说明观察到的阻碍、需要用户帮助的原因以及具体问题或操作。能根据已有信息修正的问题应先自行处理；不能确定正确输入或用户意图时，应请求帮助，不编造数据或反复提交同一份无效表单。

## 用户操作

- 需要页面操作时，探索显示「需要你处理」。点击「打开当前页面」，在网站完成操作，再点击「我已处理，继续探索」。密码和验证码在网站填写。
- 需要补充信息时，探索显示具体问题。在下方输入框回复并发送，即可继续。
- 等待期间不执行后续探索动作，不调用模型轮询。刷新界面或重启探索服务后，等待原因仍保留。
- 继续时重新连接原页面并读取最新状态，保留登录、表单及当前位置。原页面关闭或浏览器实例变化时会报错，不接管其他页面。

## 执行约定

浏览器探索的模型响应增加 `user_intervention`。普通执行和完成时为 `null`；请求介入时包含：

```json
{
  "reason": "ambiguous_project",
  "message": "发现多个同名项目，请确认目标项目。",
  "mode": "input"
}
```

`reason` 是自由文本，不按白名单限制模型判断。`mode` 为 `browser`、`input` 或 `either`，决定界面如何引导用户。请求介入时必须同时满足 `python_code` 为空、`done` 为 `false`、`final_response` 为空；冲突输出作为格式错误处理，不执行其中的页面动作。

有效请求保存为 `Paused` 退出记录并映射到 `waiting_for_user`，不会记为探索成功。现有恢复接口接收用户补充或处理确认；重复恢复请求不会同时启动多个执行进程。恢复前读取新页面观察，并保留此前的问题与用户回答。每次明确继续获得新的有限步数额度，累计调用统计保留。

页面绑定按浏览器实例与页面标识恢复，执行时仍遵守共享浏览器的页面占用规则。等待采用现有执行轮次退出机制，不新增长期占用其他任务的浏览器锁；如果等待期间页面发生变化，恢复后的最新观察作为后续判断依据。

主动请求的时机由模型判断，执行器保证收到合法请求后确实停止；这不意味着所有模型在所有网站上都会准确识别每个需要人工介入的情形。
